# 操作脚本规则

先核对操作系统、实际运行命令、包管理器、端口、环境准备和默认模式。不要从项目名称猜启动方式。多个合理模式且选择影响行为时，先完成文档，再询问；没有服务生命周期的库不强造关闭脚本。

Windows 优先 BAT 双击入口。简单命令可直接写 BAT；复杂诊断、等待或进程归属可由 BAT 调用 PS1。已有可靠 PS1 可以保留并在说明中写明运行方法。VBS 仅在明确需要无控制台且环境可用时选择；不能隐藏失败。其他系统按已有 Shell 环境生成入口，不宣称 BAT 可跨系统执行。

可参考 ../assets/launchers/ 中的极简模板，按实际项目填写，删除标记。BAT 使用 `%~dp0` 定位自身目录，`pushd`/`popd` 恢复位置；子 BAT/包管理器入口用 `call`，及时保存退出码。PS1 使用 `$PSScriptRoot`、`-LiteralPath` 和 `try/finally`。交付时验证编码、换行、中文和含空格路径；不要把 UTF-8 BOM 写进 BAT 导致首行命令异常。

启动需检查工具/配置，只有实际就绪才写“已就绪”；命令被接受但未检查健康时写“已启动，尚未验证就绪”。不要从 Vite 默认端口猜实际地址。前台命令需说明关闭终端的影响。

关闭仅限本项目：Compose 核对项目/配置；原生后台进程需记录并核对 PID、启动身份和命令归属，不能 `taskkill /IM node.exe` 等批量结束。归属不可靠时省略一键关闭并说明手动方式。停止不是删除数据库卷，禁用日常 `down -v` 或清理数据。

“重启”“构建并更新”“首次初始化”分别描述；不要自动安装依赖、下载模型、改系统设置或收费请求。长期服务不为双击便利创建无限重试。失败可见、退出码非零，等待有界。需要后台启动时窗口默认隐藏，日志提供可访问位置；交互终端仅在运行方式需要时打开。

## 配套 TXT

每组操作脚本同目录生成 `脚本使用说明.txt`，模板在 ../assets/launchers/脚本使用说明.txt。写明：

- 每个实际文件及具体动作，双击/命令行方式和推荐顺序。
- 所需工具、依赖/配置是否已准备；不要暗示双击会自动完成首次环境搭建。
- 前台/后台、窗口关闭影响、实际地址及是否检查健康。
- 停止的数据保留范围、更新与重启的差别。
- 失败如何查看窗口、日志及手动命令；仅列实际存在的信息。

有脚本就必须有 TXT；TXT 与脚本一起更新。默认进行语法检查和受控替身命令验证，不实际启停目标项目。报告哪项实测、哪项未实测。
