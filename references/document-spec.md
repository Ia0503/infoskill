# 文档规范

模板在 ../assets/documents/，只读取本次需要的编号。模板是内容骨架，不是最终文档；删除模板标记和填写提示，不机械保留不适用小节。

| 编号与文件名 | 应解释的内容 |
| --- | --- |
| 01-项目总览与架构.md | 目标、用户任务、实际功能、组件协作、完整流程和实现边界 |
| 02-目录结构与文件详解.md | 精简目录树、关键文件职责、入口和源码阅读顺序，排除依赖与产物 |
| 03-技术选型与对比分析.md | 实际技术/版本来源、需求适配、成本、替代方案和调整条件 |
| 04-核心模块深度剖析.md | 关键数据流、真实代码节选、函数定位、异常和取舍，按实际模块组织 |
| 05-测试评测与部署维护.md | 现有测试与证据、可核对的命令、环境条件、部署与维护现状 |
| 06-面试高频问题与回答要点.md | 项目介绍、重要技术追问、简短回答、深入解释、代码依据和局限 |
| 07-开发日志与阶段总结.md | 依据原日志提炼阶段、决定、失败修复、成果和遗留问题 |

全量生成前六份；第七份取决于原有有效日志。无测试/部署仍写第 05 份，说明未配置或未验证。文档开头标记日期、检查范围、可用的提交基准和未提交修改；不需要每章重复同样声明。

各篇分工：01 讲整体，02 导航，03 讲取舍，04 讲实现，05 讲验证运行，06 讲表达，07 讲过程。细节交叉链接，减少大段重复。不固定字数、模块数量、题数或求职方向。

本地 Markdown 链接使用相对路径；含空格的目标可用 `<路径>` 包裹。代码以当前源码为准，节选要有上下文并注明省略；不把示意代码说成现有实现。

技术版本读取依赖声明/锁文件，区别声明、解析和实测版本。版本相关原理必要时查官方资料；不要擅自升级依赖。不了解作者原始动机时，将选型理由写成基于实现的分析。

面试资料不编造个人分工、独立手写比例、客户规模、业务收益或性能数字；问题数量和方向由项目决定。第 07 份总结变化与经验，不复制全部流水账，也不改写原始日志。
